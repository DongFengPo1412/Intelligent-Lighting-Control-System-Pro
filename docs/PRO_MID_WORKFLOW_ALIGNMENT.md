## Mid的实际用户流程

1. 配网/激活后进入待机。`SingleLed::OnStateChanged()`使用蓝灯表示启动/联网，Idle熄灯，Listening无用户语音时暗红、检测到用户语音时亮红，Speaking绿色。具体板型可有不同LED实现，不能用一个上游板型代表所有硬件。
2. 麦克风经板端唤醒/AFE、编码队列和网络进入在线服务；服务端完成识别、模型及TTS，返回的音频由解码/播放队列输出。Mid仓库不包含可完全复现的云端模型、个人控制台配置或任意歌曲服务。
3. `application.cc`的TTS stop在自动模式转回Listening；音频通道关闭回Idle。重新进入监听时等待播放队列结束，避免尾音被切掉。
4. `HandleWakeWordDetectedEvent()`在Speaking/Listening取消旧播报、排空待发音频，并再次监听；监听/播报期间是否启用唤醒还受具体AFE与编译配置控制。当前Mid本地sdkconfig启用音频处理，但未启用`CONFIG_WAKE_WORD_DETECTION_IN_LISTENING`；不能宣传所有状态无条件完全一致。
5. 有效灯控工具把模式经UART发至WROOM。音乐由在线工具提供音源，S3分析实际播放PCM的512点FFT/16频带，再传显示；Blinker六按钮控制蛇/方块；Jetson独立手势/人脸脚本经UART切模式。它们不是一套无限能力的云端机器人，更没有目前Pro的统一多模态资源管理。

## Pro语音统一交互契约

### 2026-11-05 用户再次确认的启动顺序

用户明确要求以Mid为交互基准：初始化 → 配网/联网 → 成功提示音 → 等待唤醒词 → 短提示音与角色应答 → 监听问题/指令 → 回答后继续监听；明确结束则返回等待唤醒。上一轮双语复测没有取得新的听验结果，不据此标记通过。

本地Mid实际是**无保存Wi-Fi或连接60秒超时才进入配网**，有配置自动连接；`Application::HandleActivationDoneEvent()`在激活完成后播放`OGG_SUCCESS`，唤醒使用`OGG_POPUP`。此次复用Mid的两段通知音（原16kHz，解码为PCM16，保留MIT许可），没有更换角色权重或调整音量。

PC端已修正成功音过早的问题：本地模型、KWS、ASR、唤醒短应答先准备；PCM连接及开启麦克风获ACK、实际收到上行PCM、三个监听工作线程创建完成后，在尚未放行唤醒处理的屏障内播放成功音。播放确认后才进入等待唤醒，失败回滚并报告；重连重建监听时复用同一就绪回调，不因重复`start()`重播。单句携带唤醒名及问题，也先应答称呼再执行保留的问题。网页和旧语音启动脚本现在共用同一执行入口，不再并存USB等待循环或退出时强制亮度150的逻辑。去除启动时与当前场景无关的五组灯控台词预合成，实际用到时仍按原路径生成。

**首次配网缺口仍存在：** Pro当前固件使用已有本地配置启动AP/STA、自动连接及重连，尚未移植Mid的首次无配置Wi-Fi扫描/配网页。这是用户要求的待完成功能，不标为已移植或已实测；当前已配网设备可以独立验收语音流程。此次没有更改Flash/NVS或网络凭据；移植首次配网和实测需形成独立固件更新及具体写入授权。Mid依赖云端Opus/AFE，Pro仍使用PC本地AI与配对Wi-Fi PCM，不声称协议、识别性能或全双工能力完全相同。

待机 → 有声学证据的指定称呼 → 短提示音与对应应答 → 暗红等待收音 → 人声亮红 → 断句/识别/推理青色 → 真实播报绿色 → 中文播放期间提前准备日语 → 日语接续播报绿色 → 回到暗红继续监听。日译失败保留中文，额外等待记录在分段耗时中；没有实际声音时不能仅由灯色宣称正在发声。明确结束或空闲超时返回待机。为保持既有固件兼容，Pro待机目前仍暗红，不声称完全复刻Mid Idle熄灯。

新唤醒应取消旧轮次并停止旧PCM；确认停止后重新提示和监听，不补播旧日语。CPU/GPU正在执行的单次计算可能仍需返回，旧结果不得继续执行硬件或播报。Pro目前为PC KWS＋ASR＋实验软件回声处理，不因参考Mid而宣称已经具备板端AFE或成熟全双工。实际唤醒/打断速度和误触由真人验收。

本轮发现的确定缺陷：监听等待被错映射到固件thinking别名；旧TCP PCM与UDP abort缺少跨传输屏障，可能污染新提示音计数；已醒状态的“住手”转写未复用声学姓名确认；原“我在，请说。”实际合成约1.1秒且回读不完整。修复均在PC端，不需要新Flash写入。

称呼应答是编写的风格短句，**不是已核验的游戏原台词**：助手采用简短反驳后邀请说事；红莉栖/全名正常应答；克里斯纠正称呼；克里斯蒂娜反对擅自加蒂娜。预先合成、最多4秒，避免每次唤醒等待LLM或现场TTS；有形态/大小校验，单纯有波形不代表每个字发音都正确。
