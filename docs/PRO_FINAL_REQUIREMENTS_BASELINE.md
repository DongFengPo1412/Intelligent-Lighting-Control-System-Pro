## 2. 最后澄清与固定取舍

1. **独立 Pro 工程。** U058/U059 允许参考 Mid，并选定后续可定制的小智路线；不能为了复用而修改 Mid，也不能把“单板”解释为把大模型和电脑视觉都塞进 ESP32。
2. **角色定制基于已有开源模型。** U032/U038 提出的“训练个性化小智”经 U214 澄清为基于已有模型补充角色知识、风格、记忆和自定义能力；不是从零预训练。Prompt、RAG、现成权重和 Modelfile 各自如实命名，LoRA 不默认成为交付条件。
3. **正式正常交互必须走 Wi-Fi。** U219/U220/U222 明确：USB 接电脑供电与独立供电两种情况下，日常交互均应使用 Wi-Fi。该要求覆盖控制以及板载麦克风/扬声器与 PC 的正常音频链；不能把 USB 音频作为满足无线要求的正式降级。USB 可保留用于烧录、诊断或历史对照。
4. **Web 可以封装 Android APP。** U214 接受先完善 Web 再封装移动端。最终目标包括可安装、可控制的手机 APP；只完成网页或 APK 构建不等于手机实装已验收。无需为了形式另造第二套前端。
5. **待唤醒才能开始交互。** U165/U200/U204 要求上电联网、可理解的就绪提示、等待唤醒，再进入收句与回复。U233 及后续反馈采用“助手”；不擅自恢复早期日语名字作为唯一唤醒词。静默、背景噪声及自身播报不能自动变成用户指令。
6. **保护用户已选定的声音和显示。** 中日对应、角色声线、桌宠局部像素取舍、圆形表情、当前灯板映射和音乐光环均有后期约束。历史反馈只证明相应版本与场景，不能作为当前整机重新通过的证据，也不能因“优化”而无依据改掉。
7. **不再无限扩大优化范围。** 本轮聚焦确定的 P0/P1 执行断链、资源归属、依赖、构建和交付事实；普通 P2 记录后收尾。C.1 未执行/不存在的部分如实保留，不用新增大批优化换取“全完成”标签。
