# Pro 最终实机验收顺序

依据用户提供的两份最终验收任务书和最新反馈执行。本文件组织顺序，不替代 `PRO_FINAL_REQUIREMENTS_BASELINE.md` 的R01–R12或 `PRO_FINAL_ACCEPTANCE_MATRIX.csv` 的51项能力证据。

## 固定顺序

1. 本地大模型与智能语音对话：唤醒、ASR、角色身份、开放问答、连续对话、记忆、中日语音、时间/天气及错误恢复。
2. 自然语言语义灯光控制：有效灯效、亮度、否定指令、倒计时、世界线及真实ACK。
3. 智能音乐播放与灯光随动：真曲库/点歌、扬声器、FFT/MIR、切歌/停止及音频优先级。
4. LED Mini Arcade 100：统一大厅/说明、Web/APK、合法按键与代表性实体游戏、高分和释键。
5. 多模态视觉与交互游戏：真实摄像头、手势/指尖、头姿/凝视、人脸、失踪安全及正式卡带联动。
6. 红莉栖桌宠与整机融合：既有形象/动画、说话/昼夜/在席反馈、自动与手动优先及跨模式恢复。

六模块之后进行联合稳定性验收。不得因一个场景通过而宣告整模块通过；模块获用户确认后才进入下一模块。不重做已确认的基础深蓝，不自动刷写或清NVS。

## 反馈式执行规则

先准备环境、收集自动检查证据，再给出一个明确的现场问题框，写出当前编号、用户操作、预期效果及失败现象。问题框出现后，**停止所有工具调用、日志读取、代码修改和下一项测试**，直至用户回答。没有答复就保持等待。正式语音服务可以保持运行，以响应用户正在验收的语音；不并行启动其他模块测试。

收到反馈后才读取对应日志、记录PASS/FAIL/PARTIAL/BLOCKED/NOT_TESTED或USER_CONFIRMATION_PENDING；失败先修复和复测。源码、软件验证、实体运行与用户判断分别保留。

| 模块 | 标准操作与测试用语 | 预期结果与判断证据 |
| --- | --- | --- |
| 1 语音/本地AI | 逐个说配置唤醒词；听短音和应答后问“你好，你是谁？”；另测“什么是幸存者偏差？”、“给我讲个笑话”；正常结束后不重新唤醒，追问“再举个例子”；播报中/思考中分别再次唤醒；最后说“结束对话” | 每项独立测试。待机须声学证据唤醒，回答切题、身份正确；中文后接等义日语，日译失败中文保留；正常回答后继续监听，新唤醒终止旧轮次并重新应答收音；明确退出或空闲超时后待机。时间问题用PC实际时钟核对，天气无可靠实时来源须诚实说明。隔离记忆测试另测存储/更正/删除/重启，不能污染个人库。 |
