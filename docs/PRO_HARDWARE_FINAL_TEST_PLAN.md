## 反馈式执行规则

先准备环境、收集自动检查证据，再给出一个明确的现场问题框，写出当前编号、用户操作、预期效果及失败现象。问题框出现后，**停止所有工具调用、日志读取、代码修改和下一项测试**，直至用户回答。没有答复就保持等待。正式语音服务可以保持运行，以响应用户正在验收的语音；不并行启动其他模块测试。

收到反馈后才读取对应日志、记录PASS/FAIL/PARTIAL/BLOCKED/NOT_TESTED或USER_CONFIRMATION_PENDING；失败先修复和复测。源码、软件验证、实体运行与用户判断分别保留。
