# 交互稳定性修复与实测记录

## 修复范围

- 语音半句采用跨语音段文本缓存，不再持有普通互斥锁递归调用识别函数。覆盖“我想看……红灯”和“助手，我想看……红灯”两种情况。
- 语音回调等待模型推理和播报结束后才恢复收音。手机文字请求与语音请求统一排队，Agent 也串行处理，并按完整轮次保留近期上下文。
- Wi-Fi 命令携带请求编号。PC 等待对应板端回执；超时重试沿用同一编号；板端缓存近期结果，避免倒计时、游戏操作被重复执行。同一编号对应不同内容会被拒绝。
- 正常控制命令经 Wi-Fi 发送；USB 继续承载当前音频数据。播放期间麦克风控制也改走 Wi-Fi，并恢复播放前的监听状态。
- 板端分发器返回真实识别/参数验证结果。非法模式、无效表情状态、错误游戏动作及超范围参数返回错误。
- 网页收到失败响应时不宣告模式或倒计时启动成功。状态分别报告 Wi-Fi 控制、USB 音频和近期板载麦克风数据，设备查询不再返回固定默认模式。
- 同一轮对话的工具调用去重；文本动作已经执行后，不再无条件运行关键词兜底。工具失败时返回未确认状态。
- 翻译失败不使用固定日语句子替代，保留中文文本并暂停该次双语播报；模型离线的规则回复明确标注降级。
- 缓存经回执确认的板端地址并主动探测状态，减少对手机热点广播的依赖；可用 `KURISU_BOARD_IP` 指定首次探测地址。缓存 `.device_state.json` 已加入 Git 忽略。
- 手机访问地址按到板端的路由选择，避免误用 VPN 虚拟网卡地址。
- 提示音走统一 PCM 播放路径，音频输出互斥；I2S 写入有有限超时，休眠定时器不在播放中关闭 DMA。UDP 任务栈增至 8 KB。经过这些修复后，原先提示音回执超时的实测场景通过。
- Wi-Fi 重连等待移出共享事件循环，补充断线原因记录和 WPA3 SAE/PMF 配置。

保留原有灯效算法、桌宠图像、配色与默认亮度。现有用户改动保留，没有提交或推送 Git。

## 使用与限制

- 电脑、手机和板子需要处于可互通的网络。当前热点下电脑地址为 `192.168.45.90`，板端地址为 `192.168.45.161`；DHCP 地址可能变化，以服务状态为准。

- 当前声音数据仍通过 USB，不宣称外部独立供电时的完整无线语音功能已经实现。

## 现场反馈后的第二轮修复（2026-10-21）

用户报告：想看蓝灯时没有变蓝，回复等待很久，唤醒和对话声音极小、音质差。
历史运行日志中有指令被识别为无关文本的记录，不能把问题只归因为灯效映射。

- 明确、完整的红/蓝/绿换色指令先发送 Wi-Fi 控制、等待回执，再给出短双语确认；普通聊天保留原 kurisu 大模型。快速解析不接管否定、比较、疑问或复合句。
- Whisper Base 增加红灯、蓝灯、绿灯的领域提示，beam size 3→5；消除 VAD 起始帧重复追加。后续保存最近一次已唤醒指令的音频和识别质量指标到本地忽略目录，便于分析实人口音、削波和背景噪声；真人识别准确率仍待复测。
- 移除合成语音的强平稳降噪和人工频段提升，改为 60Hz 高通、有效语音 RMS 电平调整和软限幅。默认软件音量 90%，板端默认 85%。不以达到最大峰值代替平均响度。
- MAX98357A 改为左右两个 I2S 时隙发送相同信号，避免通道选择或平均模式造成信号损失。参考 Espressif I2S 文档及 Analog Devices MAX98357A 数据手册；具体模块接线模式未现场测量。
- 板载播报时不再同时从电脑扬声器播出另一份音频，避免两路延迟产生回声。
- 新生成短唤醒词与蓝灯确认语音，使用现有 Kurisu GPT-SoVITS 权重；语音缓存按文本、音量和处理版本区分，最多保留 64 项。没有使用微软语音。
