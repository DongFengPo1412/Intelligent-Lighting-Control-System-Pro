# 牧濑红莉栖桌宠：按部位视觉调色

日期：2026-10-22。接续 `KURISU_SRGB_RENDERING.md`。用户确认 sRGB 参考版稍有改善，但仍偏浅，明确要求以所描述的实物观感为准，允许修改 LED 输出配色。

## 配色目标

- 头发：深红色占主体，深棕色外框；暗发、高光和主体分开，高光仍偏暖红，避免浅粉大片混合。
- 面部：暖肉粉色，与白色眼角、紫色瞳孔明确区分。
- 眉眼：特别深的紫色上眼睑，浅紫上眼眸、更浅紫下眼眸。
- 衬衣：受控的浅蓝白；红领结是全图最强的纯红驱动，作为视觉强调点。
- 外套：咖啡棕色，与偏红的头发分离；倒数第二行中央四格作为更深的咖啡色裤子。
- 鞋子：近黑的中性暗灰微光，衣物暗缝保留暗光；背景仍为零输出。

## 实现

`scripts/update_kurisu_sprites.py` 将源图颜色、部位标签和 LED 驱动颜色分开保存。源图的 256 格仍可与独立采样基准逐项比较；生成的固件帧采用用户描述对应的 LED 配色。现有像素形状、走线、模式编号和动画选择逻辑不变。

参考全局亮度仍为 20/255。用下表的整数 PWM 目标反算驱动色值，向上取整为 `ceil(target * 255 / 20)`，保证在原来的整数缩放输出下恰好得到目标值。桌宠系数改为 100%，生成帧不再重复经过 sRGB 解码；其他灯效仍使用原来的显存和输出逻辑。网页全局亮度控制继续按比例生效。

| 部位 | 亮度 20 时的目标 PWM（R,G,B） |
| --- | --- |
| 深棕发框 | 3,2,1 |
| 深红主发色 | 9,1,1 |
| 暗发 | 4,1,0 |
| 暖红高光 | 13,3,1 |
| 深紫眉眼线 | 2,0,3 |
| 上眼眸 | 6,2,9 |
| 下眼眸 | 10,5,13 |
| 暖肉粉肤色 | 12,5,4 |

以上是待现场观察的驱动配方，不是屏幕色号，也不是对灯板实测的色度或亮度。最强红通道不等于已测得整幅最高物理亮度。白色区域最大通道仍控制在 12，避免把整幅总亮度一起提高。

## 第四轮：三组均偏橙，实验性暗部细分

用户反馈第三轮三个外框都类似橙色，均不符合深棕要求，可考虑用于外套。本轮不将其用作正式外框，也不提前修改外套。

上一轮的三个候选仍把绿色固定在 PWM 1，增加红色以调整色相，没有充分降低外框亮度。现有正式输出逐通道取整数；绿色低于 1 会直接归零。因此本轮只在独立诊断程序中尝试四相时间平均，取得小于 1 的平均输出。参考 [FastLED temporal dithering 说明](https://github.com/FastLED/FastLED/wiki/FastLED-Temporal-Dithering) 的思路，代码仍使用现有 ESP-IDF DisplayHAL，没有引入 FastLED 依赖或修改正式渲染器。

| 标记 | 外框四帧平均 PWM（R,G,B） | 实验目的 |
| --- | --- | --- |
| 1 点 | 1.5,0.5,0 | 降低上一轮 3,1,0 的亮度 |
| 2 点 | 1,0.25,0 | 更暗，并降低绿色比例 |
| 3 点 | 1,0.25,0.25 | 在第二组基础上尝试降低橙色鲜艳感 |

这里的平均值是数字输出的四帧算术平均，不是灯板色度或实测亮度。每格按位置错开相位，避免整个外框同时明灭；四相仍可能带来可见颜色跳动，不能宣称无闪烁。板端测得第一组连续刷新约 123.1 帧/秒，四帧周期约 30.8 次/秒。是否可用必须同时通过用户对颜色和稳定性的观察。

其他部位先按正式亮度 20 的原整数运算转换，再在诊断程序内部以全局 255 原样发送这些 PWM 字节，实际输出字节不变；仅外框按四相更新。全局 255 不代表把整个人物提亮。主发、暗发、亮发保持上一轮的 3／1／5 红通道，四格肤色和其他角色均未修改。

实验固件编译成功（233456 字节），COM9 写入校验通过；启动日志确认进入方案 1／2 并输出刷新率。本轮只修改独立诊断程序，正式配色和业务代码不变。当前板上仍为无语音／网络服务的循环比较，等待现场反馈，尚无外框颜色通过验收。日志和二进制位于忽略目录 `firmware-s3/build/hair_fractional_validation/`。本地本轮构建启用了 `PRO_HAIR_CALIBRATION=ON`；恢复正式应用时必须显式以 `-DPRO_HAIR_CALIBRATION=OFF -DPRO_MATRIX_DIAGNOSTIC=OFF` 重新构建／烧录。
