## 构建和实机边界

ESP-IDF 5.5.4真实构建，16MB双6MiB OTA分区未改。APK 2.0.1(13)已构建并v2/v3签名验证；未安装。运行内存、栈余量、输入到LED延迟、音频DMA实际断续尚无物理数据。详见[首次部署准备](ARCADE_PHASE_C_HARDWARE_READINESS.md)。

最终Python发现2183项：2182通过、1项条件跳过（可选WASM产物未提供）；JS通信16项通过；C++原B3的216局与额外51局通过，含生产音频忙碌/短写/抢占策略和JVM UDP回环；100款HTTP生命周期、WebSocket限流与Chromium目录/组合键检查通过。交互回归28项、语义规划7项另行通过，未与上述发现集混算。

一次并行构建下音乐调度测试测得203ms超过原200ms阈值；失败日志保留，未改音乐代码或降低断言。停止并行构建后，7项音乐测试和2183项全套均复核通过。该计时波动不据此断言已定位生产故障或已证明音乐性能无风险。

ESP-IDF生成BIN为1196672字节（0x124280），6MiB App分区剩5094784字节（约81%）；静态DIRAM为225463/341760字节（65.97%）。这是链接与分区数据，不是运行时剩余堆。APK打包14个网页资产与当前源文件逐字节一致。

三款短局已增加结构，但仍不应宣称真人挑战性通过：最短合法脚本中#060三房间35 tick（约0.58秒逻辑时长）、#069比赛271 tick（约4.52秒）、#089三波火情125–128 tick（约2.08–2.13秒）。脚本每步可立即给出正确输入，不包含人类思考与触控；后续仍需关卡多样性、手感与真人难度评价，不能用“路径变长”代替好玩。
