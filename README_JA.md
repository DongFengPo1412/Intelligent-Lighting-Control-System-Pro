# Intelligent Lighting Control System — Pro

PC上のローカル音声エージェントとESP32-S3を連携させる、LEDパネル・ピクセルキャラクター・ゲームの開発プラットフォームです。

[简体中文](README.md) · [English](README_EN.md) · **日本語**

**詳細：** [ソースと構成](docs/technical-notes.ja.md#source-map) · [音声と意味解析](docs/technical-notes.ja.md#voice-agent) · [描画とゲーム](docs/technical-notes.ja.md#display) · [視覚とスペクトル](docs/technical-notes.ja.md#vision-audio) · [実装範囲](docs/technical-notes.ja.md#implementation-status) · [導入](docs/setup.ja.md)

Proは**Basic → Mid → Pro**の上級開発プロジェクトです。PCで音響ウェイク検出、音声認識、ローカル言語モデル、意味解析、音声合成を実行し、ESP32-S3がLED、I2Sマイク／スピーカー、ゲーム、カウントダウンを担当します。ブラウザとAndroid WebViewはPCサービス経由で操作します。

定型オフライン語彙の[Basic](https://github.com/DongFengPo1412/Intelligent-Lighting-Control-System-Basic)、ESP32 2台とJetsonを使う[Mid](https://github.com/DongFengPo1412/Intelligent-Lighting-Control-System-Mid)から発展し、表示を1台のS3へ統合、モデル処理をPCへ移し、応答確認と重複要求処理を追加しました。

## 現在の構成とデータ経路

```mermaid
flowchart LR
    Mic[INMP441 マイク] -->|I2S| S3[ESP32-S3]
    S3 -->|USB PCM| Voice[PC VAD と KWS と Whisper]
    Voice --> Agent[ローカルOllamaと計画検証]
    App[ブラウザ または Android WebView] -->|HTTP| Host[PC aiohttpサービス]
    Host --> Agent
    Agent -->|Wi-Fi UDP命令とACK| S3
    Agent --> TTS[GPT-SoVITS音声合成]
    TTS -->|USB PCM| S3
    S3 -->|I2S| Speaker[MAX98357Aとスピーカー]
    S3 -->|RMT DMA| Matrix[1枚の16x16 WS2812B]
```

**制御はWi-Fi UDP、基板の音声は引き続きUSBです。** WebSocketはPCとブラウザ間のイベント通知で、基板の音声経路ではありません。現在はウェイク後に1命令を処理して待機へ戻る単発対話で、発話中の同時聴取は実装していません。

## 実装済みの主要モジュール

| モジュール | 実装 | 現在の制約 |
| :--- | :--- | :--- |
| **表示の統合** | ESP-IDF `led_strip`のRMTでDMAを有効化し、共通蛇行変換とCore 1描画タスクを使用。 | アプリRGBバッファは1個、通常表示に33 ms待機。ダブルバッファ、CPUゼロ、安定60 FPSとは主張しません。 |
| **ローカル音声入力** | WebRTC VADで分割、Sherpa ONNX KWSで音響ゲート、その後faster-whisper `base`で確認・転写。 | PCで実行。語は助手／红莉栖／克里斯／牧濑红莉栖、命令待ちは10 sです。 |
| **意味解析制御** | `qwen2.5:7b`に基づくOllama `kurisu`の計画を、効果名・引数・矛盾で検証して実行。 | 完全な定型命令は直接処理。雑談文から自動実行せず、Mem0やベクトル記憶はありません。 |
| **二言語応答と再生** | 外部GPT-SoVITSキャラクター重み、中国語／日本語合成、後処理、32 kHz→16 kHz変換。 | モデルと参照音声は別途準備。本リポジトリで独自学習した音声モデルではなく、翻訳・聴感の完全性も保証しません。 |
| **照明・キャラクター・計時** | 表示設定、炎、コード雨。4フレームで再生状態の口パクとランダム瞬き、経過時間に応じた消灯。 | 音素同期ではなく、終了時は約1.5 sの提示アニメーション。物理的砂粒の計算ではありません。 |
| **ゲームと操作端末** | スネーク／テトリス、Webのモード・輝度・音量・計時・ゲーム操作、Android WebView。 | Web表示は独立2Dシミュレーションで、ピクセル読戻しではありません。速度は得点・行数で変化し、表情に基づくDDAはありません。 |

ジェスチャ、顔登録、PC音声入力のスペクトルには個別実行プログラムがあります。既定Webサービスはこれらを統合起動しません。依存と未接続部分は[技術ノート](docs/technical-notes.ja.md#vision-audio)を参照してください。

## 主な設計

- **応答を確認する制御：** PCの各要求に`request_id`を付け、基板はモード・計時・音声統計を返します。重複結果のキャッシュにより、再送でタイマーやゲーム操作を繰り返さないようにします。
- **計画と実行の分離：** 効果一覧、数値設定、雑談、要確認を分け、操作数と引数範囲を検査します。不正計画の修正は1回までとし、ACKなしでは成功を読み上げません。
- **音声受信と出力の分離：** USBフレームを32 KiBリングバッファへ入れ、別タスクでI2Sへ書きます。PCは受信・書込・破棄・エラー数を照合し、送信完了だけを再生成功と扱いません。
- **原画とLED配色の分離：** 独立した256画素基準、部位上書き、LED出力配色設定を生成器で確認し、ユーザーによる修正を保護します。未達の色の目視評価も記録します。

## クイックスタート

1. [ハードウェア表](docs/setup.ja.md#hardware)で1枚16×16、INMP441、MAX98357A、USB・電源を確認します。
2. `firmware-s3/main/wifi_config.example.h`を同じ場所の追跡対象外`wifi_config.private.h`へコピーし、自分のネットワークを設定します。
3. パネル・配色診断を明示的に無効化してESP-IDFの完全アプリを構築します。依存宣言はIDF>=5.0、最近の既存記録は**v5.5.4**です。
4. Python、Ollama、ASR／KWS／TTSモデルを準備し、[導入ガイド](docs/setup.ja.md#pc)で`pc-agent-vision/web_server.py`を起動します。起動はデバイスを初期化し、確認音が鳴る場合があります。
5. PCは`http://localhost:8080`、スマートフォンはログのPC LANアドレスを開き、先に`/api/status`を確認します。

## 保守と検証

2026-10版では周波数項目・範囲を検査し、拒否を呼出し元へ返します。500 msの断流後は目標をゼロにして減衰し、ゼロ入力で底行・ピークを点灯し続けません。Snakeは食物回避、旧末尾保持、満盤終了、各ステップ1回の方向確定を修正し、80 msを厳密下限としました。Tetrisは100 msを下限とし、描画、モード・ゲーム・周波数入力、輝度、計時を共通の再帰ミューテックスで保護します。

倒計時は1–86400の整数秒を指定する専用命令を使います。直接モードは0–24のうち18を除き、時間なしの25はPC・ツールSchema・ファームウェアで拒否します。独立のジェスチャー・周波数スクリプトはWi-Fi制御状態を確認し、有効な輝度20へ戻します。USB音声接続は制御の前提ではありませんが、カメラ・モードの統一調停は未実装です。

公開ネットワーク例を使った隔離ESP-IDF 5.5.4ビルドが成功し、イメージは874800バイトです。実C++エンジン11件とPython制御・資源解放9件が通過しました。C++は模擬時計・LED HAL、Pythonはシリアル・UDP・マイク・モデル未接続です。書込、録音、発音、新たな実機受入試験は行っておらず、過去の聴感・実機記録は本修正版の評価ではありません。
